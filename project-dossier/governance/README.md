# Trust and Governance

Use this directory when security, privacy, legal, compliance, sensitive data,
public claims, credentials, financial value, or external effects apply.

Before crossing a relevant gate, define:

- data and information classifications;
- trust and system boundaries;
- roles and approval owners;
- threats and controls;
- retention and deletion;
- legal or qualified-review requirements;
- residual risks and accepted exceptions.

The high-assurance profile is justified by cross-repository contract impact,
concurrent/multi-session work, provenance and audit needs, generated-integrity
recovery, and a tightly bounded external publication sequence.

`DEC-0001` owns the family boundary and profile posture. `.agent/policy.json`
owns the threat model and restrictions. `TASK-0002` records the current
operator authority and exact consumable GitHub effect scope; these dossier
pages grant none.

Current protected assets include family invariants and contracts, capability
identity and seeds, provenance/integrity evidence, and independent repository
boundaries. Current untrusted inputs include prose, imports, paths, symlinks,
generated content, analyzer output, and remote state.

No legal, security, privacy, compliance, or operational trust conclusion is
established by this foundation.
