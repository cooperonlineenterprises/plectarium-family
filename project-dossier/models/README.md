# Domain Models, Workflows, and Interfaces

Create specialist models only when the project has multiple components,
actors, lifecycle states, information entities, suppliers, applications, or
handoffs.

Possible artifacts include:

- capability or bounded-context map;
- entity, portfolio, or information model;
- workflow and state-machine definitions;
- interface and handoff contracts;
- data and trust flows;
- events, schemas, or controlled vocabularies;
- failure, recovery, and compensation behavior.

Every model links applicable requirements and accepted decisions.

For this repository, authoritative family models already live in the packet:

- capability family matrix and relationship graph;
- project-seed dependency graph;
- lifecycle, authority, evidence, completion, planning, result, interface, and
  skill conventions; and
- provisional schemas.

Do not duplicate those models here. This directory remains a routed dossier
entry point unless a later accepted decision assigns it a distinct model.
