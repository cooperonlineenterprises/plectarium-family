# Transition and Migration

Use this package when adopting the blueprint into an established project or
replacing a prior dossier, harness, architecture, process, or implementation.

Required transition views:

- authority and decision delta;
- file and concept crosswalk;
- compatibility classification;
- migration sequence;
- stop, continue, and pause rules;
- rollback;
- adoption checklist;
- verified supersession.

Current transition: generated Project Blueprint 1.0.0 high-assurance snapshot
to a project-specific family repository under `TASK-0001` and `DEC-0001`.

- Direct equivalents: root instructions, seven-file kernel, state, records,
  generated integrity, dossier entry points, and constrained capabilities.
- Project sources adopted: versioned family packet and the historical
  canonical identity source.
- Reconciliation rule: edit the generated snapshot deliberately; never
  scaffold over the nonempty target or transfer Verity/project-blueprint
  facts, permissions, evidence, endpoints, or readiness.
- Current status: local adoption, validation, integrity, review, exact private
  repository creation, and bounded publication complete under `TASK-0001` and
  `TASK-0002`; final closure equality is direct post-commit evidence.
- Rollback: preserve source/provenance and record successor decisions; do not
  silently restore a generic baseline over accepted project content.
