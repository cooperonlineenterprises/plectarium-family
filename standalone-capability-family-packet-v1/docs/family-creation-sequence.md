# Capability Creation Sequence Rationale

1. **Verity — Universal Code Audit** — strongest completed architecture, read-heavy repository intelligence, adapters, findings, skills, OCI, and Octon boundary.
2. **Titra — Verification Assurance** — tests execution-centered permissions, claims, proof portfolios, mutation/property evidence, and false-proof control.
3. **Ortha — Specification Conformance** — tests source authority, ambiguity, traceability, and imported results.
4. **Genea — Supply-Chain Intelligence** — tests standards, changing external intelligence, provenance, licensing, and offline/network operation.
5. **Echo — Runtime Investigation** — tests workload identity, instrumentation, controlled execution, telemetry, and causal uncertainty.
6. **Harmia — API / Contract Assurance** — tests protocol diversity and static plus behavioral compatibility.
7. **Iris — UI / Browser Assurance** — tests controlled browser environments, origins, sessions, accessibility, and visual evidence.
8. **Janus — Database / Migration Assurance** — tests ephemeral controlled data environments and strict no-production-write authority.
9. **Atlas — Infrastructure Assurance** — tests plan/provider execution, state secrets, cloud read access, and strict no-apply authority.
10. **Sibyl — Release Assurance** — intentionally late; validates durable cross-capability aggregation without tight coupling.

Steps 4–9 may be reordered or parallelized according to real project demand after the three-capability convention checkpoint.
