# Criteria for Adding a Family Capability

A proposal should answer:

1. What governing question is distinct from existing capabilities?
2. What substantial domain logic or specialist toolchain does it own?
3. Why is independent use valuable outside Octon Mini?
4. What evidence and completion semantics are unique?
5. What permissions/security posture differ materially?
6. Why would embedding it in a sibling capability or harness create a monolith?
7. What durable result should it produce?
8. What evaluation corpus is required?
9. What downstream consumers exist?
10. What should remain an adapter or project-local helper instead?

Approval requires a capability seed, relationship analysis, authority review, threat model, project-generation prompt, and an accepted family decision. Family membership does not imply a hard dependency or common implementation language.
