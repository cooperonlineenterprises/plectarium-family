# Universal Code Audit Mature-v1 Release Criteria Seed

A project-generation agent must turn these into a precise claim-proof matrix.

- independent CLI operation without Octon Mini, MCP, or AI
- one authoritative engine across released interfaces
- valid, documented, verifiable UCA Audit Bundle
- truthful completion for missing/denied/failed/stale/partial evidence
- explicit permission planning and no hidden installation/network
- domain-specific golden, near-miss, adversarial, security, and large-subject evaluation
- stable result identity, comparison, provenance, and corruption detection
- signed/checksummed release artifacts with SBOM/provenance as applicable
- canonical Agent Skill with routing and authority tests
- canonical character identity **Verity** propagated without aliases or authority expansion
- documented limitations and capability depth rather than a misleading supported yes/no claim

## Domain-specific release outcomes

- conclusion states are precisely defined: deterministic_violation, deterministic_regression, runtime_confirmed, historical_hotspot, investigation_required, evidence_gap, simplification_opportunity;
- evaluation establishes: top-k finding precision, candidate rejection quality, stable fingerprints, truthful partial completion, read-only proof, reduction safety-floor preservation;
- domain threats have passing controls: malicious repositories, hostile build scripts, untrusted analyzer output, prompt injection in source/documents, cache poisoning, path traversal and symlinks, hidden tool installation;
- selected adapters/providers have version matrices, contract tests, and named owners;
- mature target is satisfied: A production-grade, language-aware, local-first audit engine with CLI, CI, MCP, OCI, durable evidence, stable comparison, deep Rust/Python support, useful TypeScript/JavaScript and Go support, selected mature adapters, and two evaluated Agent Skills.

A high feature count does not substitute for coherent evidence, completion, security, and interface semantics.
