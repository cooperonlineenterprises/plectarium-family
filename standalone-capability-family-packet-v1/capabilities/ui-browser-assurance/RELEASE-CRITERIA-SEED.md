# UI / Browser Assurance Mature-v1 Release Criteria Seed

A project-generation agent must turn these into a precise claim-proof matrix.

- independent CLI operation without Octon Mini, MCP, or AI
- one authoritative engine across released interfaces
- valid, documented, verifiable UI Assurance Bundle
- truthful completion for missing/denied/failed/stale/partial evidence
- explicit permission planning and no hidden installation/network
- domain-specific golden, near-miss, adversarial, security, and large-subject evaluation
- stable result identity, comparison, provenance, and corruption detection
- signed/checksummed release artifacts with SBOM/provenance as applicable
- canonical Agent Skill with routing and authority tests
- canonical character identity **Iris** propagated without aliases or authority expansion
- documented limitations and capability depth rather than a misleading supported yes/no claim

## Domain-specific release outcomes

- conclusion states are precisely defined: journey_passed, journey_failed, accessibility_violation, visual_regression, browser_incompatibility, performance_budget_failed, incomplete;
- evaluation establishes: known journey failures, accessibility near-misses, visual baseline stability, cross-browser variance, origin/network containment, secret and session isolation;
- domain threats have passing controls: malicious web content, browser escape, credential/session leakage, untrusted downloads, external communication, production data changes, visual-baseline poisoning;
- selected adapters/providers have version matrices, contract tests, and named owners;
- mature target is satisfied: A reproducible multi-browser assurance engine with isolated sessions, journey plans, accessibility and performance checks, visual evidence, stable baselines, rich traces, and strict origin/credential controls.

A high feature count does not substitute for coherent evidence, completion, security, and interface semantics.
