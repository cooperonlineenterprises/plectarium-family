# Infrastructure Assurance Mature-v1 Release Criteria Seed

A project-generation agent must turn these into a precise claim-proof matrix.

- independent CLI operation without Octon Mini, MCP, or AI
- one authoritative engine across released interfaces
- valid, documented, verifiable Infrastructure Assurance Bundle
- truthful completion for missing/denied/failed/stale/partial evidence
- explicit permission planning and no hidden installation/network
- domain-specific golden, near-miss, adversarial, security, and large-subject evaluation
- stable result identity, comparison, provenance, and corruption detection
- signed/checksummed release artifacts with SBOM/provenance as applicable
- canonical Agent Skill with routing and authority tests
- canonical character identity **Atlas** propagated without aliases or authority expansion
- documented limitations and capability depth rather than a misleading supported yes/no claim

## Domain-specific release outcomes

- conclusion states are precisely defined: coherent, coherent_with_conditions, policy_violation, destructive_change, privilege_expansion, exposure_change, high_risk, incomplete;
- evaluation establishes: known destructive plans, near-miss safe changes, privilege-delta accuracy, state/secret redaction, no-apply proof, provider/network isolation;
- domain threats have passing controls: provider code execution, cloud credential theft, state-file secrets, plan manipulation, destructive apply confusion, remote-state access, untrusted custom policies;
- selected adapters/providers have version matrices, contract tests, and named owners;
- mature target is satisfied: A multi-format infrastructure assurance engine that safely parses or generates plans, models resource and privilege change, integrates policy tools, detects destructive/exposure changes, and operates without apply authority.

A high feature count does not substitute for coherent evidence, completion, security, and interface semantics.
