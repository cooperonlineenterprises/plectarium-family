# Release Assurance Mature-v1 Release Criteria Seed

A project-generation agent must turn these into a precise claim-proof matrix.

- independent CLI operation without Octon Mini, MCP, or AI
- one authoritative engine across released interfaces
- valid, documented, verifiable Release Assurance Bundle
- truthful completion for missing/denied/failed/stale/partial evidence
- explicit permission planning and no hidden installation/network
- domain-specific golden, near-miss, adversarial, security, and large-subject evaluation
- stable result identity, comparison, provenance, and corruption detection
- signed/checksummed release artifacts with SBOM/provenance as applicable
- canonical Agent Skill with routing and authority tests
- canonical character identity **Sibyl** propagated without aliases or authority expansion
- documented limitations and capability depth rather than a misleading supported yes/no claim

## Domain-specific release outcomes

- conclusion states are precisely defined: ready, ready_with_exceptions, not_ready, incomplete, indeterminate;
- evaluation establishes: known ready/not-ready cases, stale-result rejection, scope incompatibility detection, upstream provenance preservation, exception handling, no-publication authority tests;
- domain threats have passing controls: forged upstream results, stale evidence, scope mismatch, policy manipulation, artifact substitution, readiness being mistaken for authority, credential pressure;
- selected adapters/providers have version matrices, contract tests, and named owners;
- mature target is satisfied: A policy-driven, artifact-bound aggregator that verifies upstream result identity, schema compatibility, completion, freshness, and provenance; explains unmet criteria and exceptions; and remains unable to publish or deploy.

A high feature count does not substitute for coherent evidence, completion, security, and interface semantics.
