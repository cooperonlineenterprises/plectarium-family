# API / Contract Assurance Mature-v1 Release Criteria Seed

A project-generation agent must turn these into a precise claim-proof matrix.

- independent CLI operation without Octon Mini, MCP, or AI
- one authoritative engine across released interfaces
- valid, documented, verifiable Contract Assurance Bundle
- truthful completion for missing/denied/failed/stale/partial evidence
- explicit permission planning and no hidden installation/network
- domain-specific golden, near-miss, adversarial, security, and large-subject evaluation
- stable result identity, comparison, provenance, and corruption detection
- signed/checksummed release artifacts with SBOM/provenance as applicable
- canonical Agent Skill with routing and authority tests
- canonical character identity **Harmia** propagated without aliases or authority expansion
- documented limitations and capability depth rather than a misleading supported yes/no claim

## Domain-specific release outcomes

- conclusion states are precisely defined: compatible, compatible_with_conditions, breaking_change, behavioral_mismatch, undeclared_behavior, unverified, incomplete;
- evaluation establishes: known breaking-change detection, non-breaking near-miss rejection, consumer/provider mismatch recall, stateful bug detection, safe endpoint isolation, version-policy fidelity;
- domain threats have passing controls: unsafe API fuzzing, production endpoint targeting, credential leakage, schema poisoning, consumer data exposure, false compatibility from schema-only checks;
- selected adapters/providers have version matrices, contract tests, and named owners;
- mature target is satisfied: A protocol-agnostic compatibility engine that combines static schema analysis with consumer/provider and stateful behavioral evidence, supports compatibility windows, and produces stable contract conclusions across releases.

A high feature count does not substitute for coherent evidence, completion, security, and interface semantics.
