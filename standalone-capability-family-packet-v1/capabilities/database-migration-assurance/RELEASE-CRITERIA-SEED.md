# Database / Migration Assurance Mature-v1 Release Criteria Seed

A project-generation agent must turn these into a precise claim-proof matrix.

- independent CLI operation without Octon Mini, MCP, or AI
- one authoritative engine across released interfaces
- valid, documented, verifiable Migration Assurance Bundle
- truthful completion for missing/denied/failed/stale/partial evidence
- explicit permission planning and no hidden installation/network
- domain-specific golden, near-miss, adversarial, security, and large-subject evaluation
- stable result identity, comparison, provenance, and corruption detection
- signed/checksummed release artifacts with SBOM/provenance as applicable
- canonical Agent Skill with routing and authority tests
- canonical character identity **Janus** propagated without aliases or authority expansion
- documented limitations and capability depth rather than a misleading supported yes/no claim

## Domain-specific release outcomes

- conclusion states are precisely defined: safe_within_declared_conditions, requires_staged_rollout, requires_runtime_validation, high_risk, unsafe, incomplete;
- evaluation establishes: known unsafe migrations, safe near-misses, locking/rewrite prediction, rolling-version compatibility, data-integrity preservation, no-production-write proof;
- domain threats have passing controls: production database mutation, credential leakage, sensitive data export, unrepresentative sample data, lock amplification, irreversible transformations, unsafe rollback assumptions;
- selected adapters/providers have version matrices, contract tests, and named owners;
- mature target is satisfied: A database-aware migration assurance engine with dialect-specific adapters, staged-rollout modeling, application-version compatibility, dry-run and representative-data evidence, data-loss protections, and no production mutation authority.

A high feature count does not substitute for coherent evidence, completion, security, and interface semantics.
