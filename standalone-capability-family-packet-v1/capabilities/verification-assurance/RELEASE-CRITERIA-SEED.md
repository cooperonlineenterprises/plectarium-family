# Verification Assurance Mature-v1 Release Criteria Seed

A project-generation agent must turn these into a precise claim-proof matrix.

- independent CLI operation without Octon Mini, MCP, or AI
- one authoritative engine across released interfaces
- valid, documented, verifiable Verification Bundle
- truthful completion for missing/denied/failed/stale/partial evidence
- explicit permission planning and no hidden installation/network
- domain-specific golden, near-miss, adversarial, security, and large-subject evaluation
- stable result identity, comparison, provenance, and corruption detection
- signed/checksummed release artifacts with SBOM/provenance as applicable
- canonical Agent Skill with routing and authority tests
- canonical character identity **Titra** propagated without aliases or authority expansion
- documented limitations and capability depth rather than a misleading supported yes/no claim

## Domain-specific release outcomes

- conclusion states are precisely defined: proven_within_scope, strongly_supported, partially_supported, unproven, contradicted, not_testable, verification_incomplete;
- evaluation establishes: known-claim support/contradiction recall, false proof rejection, mutation sensitivity, flaky-test handling, scope honesty, claim-to-evidence traceability;
- domain threats have passing controls: hostile tests and build scripts, test environments exfiltrating secrets, flaky/non-deterministic tests, false proof from tautological tests, stale test evidence, unsafe integration credentials;
- selected adapters/providers have version matrices, contract tests, and named owners;
- mature target is satisfied: A claim-centered verification engine that can plan and execute proof portfolios across major languages, preserve negative and missing evidence, quantify exercised scope, detect test weakness through mutation/property methods, and provide stable claim status across revisions.

A high feature count does not substitute for coherent evidence, completion, security, and interface semantics.
