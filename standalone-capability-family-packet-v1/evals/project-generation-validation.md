# Project-Generation Validation Procedure

## Inputs

- clean agent context;
- complete family packet;
- one selected capability directory;
- no original conversation;
- network access for primary-source verification where allowed.

## Required generated artifacts

The resulting capability packet should contain a charter, canonical character identity and usage rules, invariants, architecture, security model, lifecycle, evidence/conclusion/completion models, schemas, durable bundle specification, adapters, interfaces, Agent Skill, evaluation, task graph, roadmap, release criteria, decisions/ADRs, research/license/provenance, validator, manifest, checksums, transcript coverage, and archive integrity report.

## Grading dimensions

1. Family invariant preservation.
2. Capability-specific depth.
3. No unauthorized action semantics.
4. Evidence and completion truthfulness.
5. Permission/security specificity.
6. External-tool research quality.
7. Interface unity.
8. Evaluation claim-proof rigor.
9. Project roadmap executability.
10. Open-question honesty.
11. No premature shared framework.
12. Internal and machine-readable consistency.
13. Exact character-identity propagation, no aliases, and no anthropomorphic authority expansion.

## Failure examples

- merely restates the seed;
- copies UCA schemas unchanged without domain justification;
- says “tests pass” or “safe” without a scope/completion model;
- grants production apply/migration/publish authority;
- makes AI the only engine;
- omits a durable result;
- creates separate CLI and MCP semantics;
- silently installs tools;
- lacks adversarial and partial-completion tests.
- renames or abbreviates the canonical character identity, replaces explicit machine IDs with it, or treats it as authority.
