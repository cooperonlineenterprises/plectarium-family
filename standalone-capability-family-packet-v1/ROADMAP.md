# Capability Family Roadmap

**Authority:** Family sequencing and evidence-gathering plan  
**Status:** `ACCEPTED`; capability implementation schedules remain project-owned

## Stage 0 — Finalize this family packet

- establish family authority, invariants, provisional contracts, seed quality, and validation;
- preserve UCA as the mature reference;
- generate substantive seeds and project-generation prompts for all ten capabilities.

## Stage 1 — Build Verity / Universal Code Audit

Use the validated UCA Full Product Build Packet. Demonstrate one engine across CLI, CI, MCP, OCI, skills, and an Octon provider boundary.

## Stage 2 — Record observed conventions

Do not extract a framework. Record concrete implementation lessons about manifests, result identity, permissions, completion, adapters, skills, and harness invocation.

## Stage 3 — Generate and build Titra / Verification Assurance

Use `capabilities/verification-assurance/PROJECT-GENERATION-PROMPT.md`. Test whether the lifecycle supports execution-centered, claim-based evidence rather than repository audit findings.

## Stage 4 — Compare Verity / UCA and Titra / Verification

Identify actual duplication and semantic differences. Update provisional family documents through ADRs; do not force convergence.

## Stage 5 — Generate and build Ortha / Specification Conformance

Test imported evidence, traceability, source authority, ambiguity, and conflict preservation.

## Stage 6 — Three-capability stabilization checkpoint

Only now evaluate whether any v0 manifest, result-envelope, completion, permission, provenance, skill-generation, MCP, or OCI conventions deserve v1 status or a shared SDK.

## Stage 7 — Build Genea / Supply-Chain Intelligence

Prioritize adapter-rich, offline-capable component/provenance intelligence. This provides a strong test of external data freshness and standards interoperability.

## Stage 8 — Build peer specialist capabilities as demand justifies

Echo / Runtime Investigation, Harmia / API/Contract Assurance, Iris / UI/Browser Assurance, Janus / Database/Migration Assurance, and Atlas / Infrastructure Assurance may proceed in parallel once their project packets are generated and security boundaries are approved.

## Stage 9 — Build Sibyl / Release Assurance

Use it as the first major cross-capability evidence aggregator. It should consume durable results rather than invoke every specialist engine internally.

## Stage 10 — Decide whether a formal family specification or SDK is justified

Require demonstrated repeated implementation, reduced total complexity, stable semantics, and at least one non-Octon consumer. Reject extraction that merely centralizes code without clarifying authority or compatibility.
